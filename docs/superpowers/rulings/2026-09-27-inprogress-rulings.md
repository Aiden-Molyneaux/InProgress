## Known follow-ups after v1

Found in review and deliberately left for after v1:

- Under 720 px, clicking a node opens the Details sheet over it. Lift the clicked row above the sheet (first follow-up).
- A session-start POST that the server applies after the hook has given up leaves that session unbriefed until the stale-update line. Brief a session on its first prompt as well.
- `doctor` could warn when the hooks' node binary differs from the current `realpath(node)` after an nvm switch. Hook-started servers then fail to load better-sqlite3 until a reinstall.
- `claude-install` stops the running server before `install()` runs its refusal checks. A refused install leaves the server stopped until the next hook, scribe call or `inprogress start`.
- Keyboard: after Enter on "+n more", focus falls to the page body. The focus reveal ignores the narrow Details sheet. A minimap drag whose first move lands outside the minimap pans without turning Follow off.
- Details keeps a deleted node's last detail with a "Couldn't refresh" line. It could close instead.
- Reduced motion does not cover the camera's 400 ms glides.
- At 1,000+ visible rows every event rebuilds every card (accepted under the M2 ruling). Structural sharing in the Canvas `nodes` memo would fix it.
- No hook-level unit tests for `useInProgress`, `useCamera` or `useFoldOverrides` (happy-dom plus Testing Library would add them).
- Watch the scribe's first nested `add_nodes` plan: its JSON schema uses a local `$ref` for `children`.
- A few lib tests (git, home, transcript) leave temp dirs behind.
- Uninstall does not restore empty containers that existed before install, such as `"hooks": {}`. The settings backup holds the original bytes.
