# Drag project tabs to reorder them (#407)

Branch `tab-drag`, worktree `.claude/worktrees/tab-drag`, base main 210d2b6. Label `ui`: typecheck + unit, one e2e test
for the feature, no failing-test-first for styling.

## Goal

Aiden drags a project tab along the strip to reorder it, or moves the focused tab with Alt+Left and Alt+Right. The
order sticks across reloads and restarts.

## Where the order lives (main session's call)

Window `localStorage`, key `ip.tabOrder`: a JSON array of project ids, in strip order. The window already keeps its
selection (`ip.project`), its view and its folds there, and spec 7.1 says so for the selection. No migration, no server
route. The cost: another browser profile starts from the default order, which is fine for one window on one machine.

## Order rules

- Active projects with a stored position come first, in stored order. Active projects without one follow, oldest first
  (by id), so a new or unarchived project lands at the end.
- An open archived project's tab stays last. It is not draggable and Alt+arrows do nothing on it.
- A project that leaves the active list loses its stored position, so it comes back at the end: when the window sees a
  stored id listed as archived, or in the deleted list, it drops that id and saves. Ids in neither list (purged) are
  dropped on the next save, since a save writes only the active tab ids.
- Every move saves the whole active order, as shown.

## Changes

1. `web/src/chrome/tabs.ts`
   - `projectTabs(projects, current, order: number[] = [])` applies the rules above. Update its doc comment.
   - `moveTab(tabs, id, before: number | null): number[]`: the active tab ids with `id` moved before `before` (null:
     after the last active tab). Ignores the archived tab. A `before` that is `id` itself leaves the order as it is.
   - `tabDropSlot(activeIds, overId, leftHalf, dragging): number | null`: as `dropSlot` in `web/src/board/dragQueue.ts`
     but sideways: the left half of a tab drops before it, the right half before the next active tab (null: the end);
     a slot that is the dragged tab reads as the tab after it.
   - `pruneOrder(order, projects, deleted): number[]`: drops ids listed as non-active or as deleted.
   - `loadTabOrder()` / `saveTabOrder(ids)` over `loadJson` / `save` from `web/src/storage.ts`. Load keeps only
     positive integers, first occurrence of each; anything else gives `[]`.
2. `web/src/App.tsx`
   - `order` state from `loadTabOrder()`, passed to `projectTabs`.
   - An effect on `[projects, deleted]` that prunes and saves when the pruned order is shorter.
   - A `storage` event listener for `ip.tabOrder`, so a second window follows a move.
   - `onMoveTab(id, before)`: computes `moveTab`, and when it differs, sets, saves, and `noteAction('header', 'tab_move')`.
3. `web/src/chrome/TopBar.tsx` (TabStrip, and TopBar passes `onMove` through)
   - Active tabs get `draggable`. `dragstart` sets `effectAllowed = 'move'`, `text/plain` to the id, and the dragging
     id in state. `dragover` on a tab (only while dragging one of ours) prevents default and sets the slot with
     `tabDropSlot`, using clientX against the tab's midpoint; over the archived tab the slot is null (the end).
     `drop` on the strip calls `onMove` unless the order would not change; `dragend` clears state. The strip may
     need a `dragover` with preventDefault for drops in its empty area past the last tab (slot null).
   - Classes: `.ip-tab.dragging` (opacity .5), `.ip-tab.drop-before` and `.ip-tabs.drop-end` (on the last active
     tab) draw a 2px `var(--text-2)` bar at the tab's left or right edge, with inset box-shadow, matching the Next
     column's drop line. Keep the selected underline (`::after`) and the divider (`::before`) as they are.
   - Keyboard: in `onKeyDown`, before the existing arrow branch, Alt+ArrowLeft / Alt+ArrowRight (no Ctrl, Meta or
     Shift) on a tab: always preventDefault (Alt+Left is the browser's Back, and the window routes by hash). On an
     active tab with a neighbour on that side among the active tabs, call `onMove` (left: before the previous tab;
     right: before the tab after next, or null). No wrap at either end. Selection does not change. Focus must stay on
     the moved tab: after the reorder renders, if focus left it, focus it again (a ref to the moved id plus a layout
     effect on the tab ids).
   - A tab that was dragged must not also fire its click.
4. `web/src/styles.css`: the classes above, beside the `.ip-tab` rules (around line 107).
5. Spec `docs/superpowers/specs/2026-09-27-inprogress-design.md:506-510`: the strip's order is oldest first until
   Aiden drags a tab or moves it with Alt+Left/Right; the order is stored in `localStorage`; new or unarchived projects
   join at the end.
